# DeepTutor 离线课程内容工作流 Spike 设计

Status: Approved for implementation planning
Date: 2026-06-03

## 背景

GoGopher Arch 当前已经具备完整内置的 Go 基础课程、MDX 章节正文、章节 metadata、分层练习和沙盒反馈链路。项目的课程原则是：正文以内置内容为主，外部资料只能作为知识来源层，最终必须转化为 GoGopher Arch 自己的学习路径，不能用外链合集替代站内教程。

本设计要验证 HKUDS/DeepTutor 是否适合作为离线课程内容工作流工具：利用它的开放检索、资料综合和生成能力，辅助生成或改造 GoGopher Arch 的课程正文。第一轮不把 DeepTutor 接入线上用户流程，也不把它设为生产服务依赖。

## 目标

本 Spike 的优先目标是验证：DeepTutor 能否基于站内课程约束和开放网页资料，生成一版明显优于原章节的教程级 Go 课程正文草稿。

成功标准以内容质量优先：生成正文应在结构、概念深度、工程场景、示例解释和学习路径连贯性上明显优于原章节，并达到可人工审校、可维护、可决定是否保留的水平。

## 非目标

本轮不做以下事情：

- 不接入线上 AI Tutor UI。
- 不把 DeepTutor 作为生产运行依赖。
- 不批量自动改写 13 章。
- 不跳过人工审校直接认定 AI 草稿通过。
- 不让外部网页内容以拼贴或外链替代形式进入课程正文。
- 不把 LLM 输出作为课程质量的唯一判定。

AI 导师能力是后续方向。本轮只保留从内容工作流中获得的经验，例如课程上下文打包、来源审计和提示模板，供后续导师设计复用。

## 推荐路线

采用“方案 A 起步，方案 B 作为加分验证”。

### 方案 A：DeepTutor 作为外部内容研究员

第一轮使用 DeepTutor 的 Web 或交互式能力，由人工驱动完成开放检索、资料综合和章节草稿生成。GoGopher Arch 只接收经过审计的输出结果。

优点：

- 最快验证 DeepTutor 的内容质量。
- 不让 CLI/API 调试成本干扰主要判断。
- 适合当前“内容质量优先”的成功标准。

限制：

- 自动化程度低。
- 后续复用需要再沉淀脚本、输入模板或 CLI 管线。

### 方案 B：CLI 半自动管线（加分项）

如果 DeepTutor CLI 能稳定输出 JSON 或 Markdown，可额外记录一条半自动管线：用固定输入模板调用 DeepTutor，产出章节草稿和审计包。该项不阻塞本轮内容质量结论。

## 总体架构

主链路分为五步：

1. **章节审查**：审查现有 13 章，按内容深度、资料接入价值、工程场景和练习衔接综合评分，选择最适合验证的薄弱章节。
2. **DeepTutor 研究生成**：向 DeepTutor 输入原章节、站内课程约束、目标学习者、开放检索要求和输出格式，由 DeepTutor 生成教程级 MDX 正文草稿。
3. **完整审计包**：对开放资料和生成正文做来源清单、段落级来源映射、搬运风险、与原章节差异和人工审校 checklist。
4. **章节替换**：将通过初筛的正文草稿写入目标 `web/src/content/go-basics/chXX-*.mdx`。
5. **验证与决策**：运行构建与内容质量检查，最终决定保留、人工修改后保留或回滚。

DeepTutor 在此架构中是离线研究工具，不是运行时依赖。课程仓库只保留经过审计和验证的课程正文与 Spike 文档。

## 组件设计

### Chapter Auditor

职责：选择本轮最适合 DeepTutor Spike 的目标章节。

输入：

- 13 个 Go 基础章节 MDX。
- `web/src/content/go-basics/courseChapters.ts` 中的章节 metadata、目标、练习和复盘信息。
- 当前课程质量原则。

评分维度：

- 内容深度：概念是否讲清定义、语义、初始化/使用方式、常见误区。
- 资料接入价值：该主题是否适合通过 Go 官方文档、gopl-zh 和开放资料校准。
- 工程场景：是否能自然转化为后端新手到实习场景。
- 练习衔接：正文是否能支撑 warmup/core/challenge 练习。

产物：13 章评分表和目标章节选择理由。

### DeepTutor Research Session

职责：驱动 DeepTutor 做开放检索、资料综合和章节草稿生成。

输入包应包含：

- 原章节正文。
- 目标章节 metadata 和练习摘要。
- GoGopher Arch 课程风格契约。
- 目标学习者：“后端新手到实习”。
- 开放网页检索要求。
- 输出格式要求：MDX 正文草稿 + 来源审计信息。

产物：DeepTutor 生成的章节正文草稿、来源记录和生成过程摘要。

### Course Style Contract

职责：约束 DeepTutor 输出符合 GoGopher Arch 的教程风格，而不是普通博客或外链资料摘要。

正文结构应遵循：

1. 具体场景引入。
2. 基础概念逐步讲解。
3. 最小示例。
4. 工程化示例。
5. 常见坑。
6. 工程实践。
7. 概念回看。
8. 与分层练习的衔接说明。

约束：

- 不把密集概念地图放在文章开头。
- 不使用外链合集替代站内正文。
- 不直接拼贴外部教程表达。
- 示例应服务 Go 后端学习路径。

### Draft Integrator

职责：将通过初筛的草稿写入目标 MDX 章节。

行为：

- 替换目标 `web/src/content/go-basics/chXX-*.mdx` 正文草稿。
- 不自动修改 metadata 和练习，除非后续实施计划明确纳入。
- 保留 git diff 作为回滚手段。

### Audit Gate

职责：阻止来源不清、拼贴风险高或技术不准确的内容进入最终状态。

审计包应写入 `docs/superpowers/spikes/deeptutor-course-content/`，至少包含：

- 来源清单。
- 段落级来源映射。
- 搬运风险与疑似近似表达说明。
- 与原章节的结构和内容差异。
- 不可验证或需要人工确认的技术声明。
- 人工审校 checklist。
- 最终建议：保留、人工修改后保留或回滚。

## 数据流

输入：

- 站内约束：原章节 MDX、章节 metadata、课程设计原则、目标学习者和练习衔接。
- 外部资料：DeepTutor 开放网页检索、Go 官方文档、gopl-zh、高质量教程或文章。
- 质量 Rubric：准确性、深度、工程场景、示例可解释性、非拼贴、可审校性。

输出：

- 替换后的目标章节 MDX。
- 完整审计包。
- DeepTutor 能力评估结论。
- 可选 CLI 调用记录。

流程：

```text
13 章课程内容
  ↓
Chapter Auditor 评分选章
  ↓
DeepTutor 输入包
  ↓
开放检索 + 资料综合 + 正文生成
  ↓
MDX 草稿 + 来源记录
  ↓
Audit Gate 审计
  ↓
写入目标章节
  ↓
构建验证 + 内容质量评估
  ↓
保留 / 修改后保留 / 回滚
```

## 风险与错误处理

### DeepTutor 无法安装或运行

处理：不修改课程正文，记录阻塞原因和接入成本。Spike 结论可以是“内容质量未能验证，因为接入成本或运行环境不可接受”。

### 开放检索来源质量差

处理：收缩来源范围，优先 Go 官方文档、站内课程、本地 gopl-zh 和高质量教程。若来源仍不足，不强行生成或保留。

### 生成正文不明显优于原章

处理：按内容质量优先判失败。不因流程跑通、格式正确或 DeepTutor 可用而保留低质量正文。

### 来源审计不完整

处理：不允许进入最终保留状态。必须补齐审计，或回滚目标章节。

### 疑似资料拼贴或版权风险

处理：标记风险段落，要求重写。若风险无法消除，回滚。

### 技术概念不准确或不可验证

处理：关键概念必须能回指 Go 官方文档、站内标准或可信来源。不可验证表述进入人工审校 checklist；严重错误则回滚。

### MDX 或构建失败

处理：格式问题可修复；若需要大幅重写才成立，结论应记录为“人工修改后保留”或“回滚”。

## 验证策略

### 章节选择验证

- 13 章评分表存在。
- 目标章节选择理由清晰。
- 选择标准与用户确认的综合标准一致。

### 内容质量验证

按以下维度评分：

- 技术准确性。
- 概念深度。
- 场景引入质量。
- 示例解释质量。
- 工程实践价值。
- 常见坑覆盖。
- 概念回看是否放在讲解之后。
- 与练习和复盘是否自然衔接。

### 来源审计验证

- 来源清单完整。
- 段落级来源映射可读。
- 搬运风险有明确结论。
- 不可验证声明被列出。
- 人工审校 checklist 可执行。

### 技术验证

至少运行：

```bash
npm run build --prefix web
git diff --check
```

如涉及页面行为或 MDX 渲染异常，再启动前端做人工抽查。

### 决策验证

最终必须明确以下结论之一：

- **保留**：内容质量明显优于原章，审计通过，构建通过。
- **人工修改后保留**：主体质量有价值，但需要局部重写、格式修复或补充审计。
- **回滚**：内容质量不达标、来源风险不可接受、技术错误严重或构建不可接受。

## 后续 AI 导师扩展

本轮不实现 AI 导师，但保留以下可复用资产：

- 课程上下文输入包。
- Course Style Contract。
- 来源审计和不可验证声明列表。
- 章节质量 Rubric。
- DeepTutor CLI/API 可用性记录。

如果后续进入 AI 导师方向，可复用这些资产，为课程阅读、练习失败和任务复盘提供带来源约束的导师上下文。

## 实施计划入口

用户审阅并批准本规格后，下一步进入实施计划。实施计划应至少覆盖：

1. 审查 13 章并选定目标章节。
2. 安装/运行 DeepTutor，确认 Web 或 CLI 可用。
3. 准备 DeepTutor 输入包。
4. 生成章节正文草稿和审计材料。
5. 替换目标 MDX 章节。
6. 运行审计、构建和内容质量验证。
7. 输出最终保留/修改/回滚结论。
