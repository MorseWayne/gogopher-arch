# 从使用方写出最小接口

接口的价值不是把具体类型“包装得更抽象”，而是准确表达当前使用方需要的行为。本练习里，订单服务只发送通知，所以一个 `Notify` 方法就是完整契约。接口放在使用方包中，具体邮件、短信实现无需被业务层认识。

先用 spy 观察调用次数和参数，再补全业务方法。这个顺序把接口、依赖注入和测试接缝连在同一个小闭环里。完成后对照本地[接口章节](../go-basics/ch07-interfaces.mdx)，重点复习隐式实现和小接口，而不是背定义。

Go Code Review Comments 的 [Interfaces](https://go.dev/wiki/CodeReviewComments#interfaces) 条目可作为边界检查清单：接口是否由使用者需要驱动，是否为了 mock 提前制造了过大的抽象。
