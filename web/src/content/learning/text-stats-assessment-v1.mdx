# 独立完成一次核心语义组合

这次不再给出半成品循环。你需要把命名类型、零值、Unicode、分支和累计逻辑组合成完整的 `Analyze`。

## 公开契约

每条输入必须生成一条 `Entry`，分类优先级为 empty、too long、accepted。只有 accepted 项进入 `Accepted` 和 `TotalRunes`，其他项进入 `Rejected`。空输入自然返回零值报告。

公开测试只覆盖 ASCII。提交检查还会覆盖多字节 Unicode、边界值、无效上限和空输入。它验证的是规则能否迁移到未展示数据，不是你是否猜中某个样例。

## 独立证据要求

- 先自己完成并运行 Build、Test、Vet。
- 如果使用提示或 AI，平台会记录协作方式；最终独立掌握仍需要一份未使用帮助的评估证据。
- 完成小结要说明字节、rune 和用户所说“字符”之间的区别，但小结不替代代码证据。

提交前主动加一个中文或带重音字符的临时测试，再检查 `maxRunes <= 0` 和空输入。语义有疑问时按阅读目标检索[官方语言规范](https://go.dev/ref/spec)，不要复制整段答案。
