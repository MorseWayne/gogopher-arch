# 在新情境中重新证明掌握

这次复习把“读取、验证、稳定输出”迁移到配置合并场景。数据结构和组合规则已经变化，因此不能照搬上次评估的字段判断；你需要重新识别这份任务的契约。

## 这次变化在哪里

| 之前的任务 | 本次变式 |
|---|---|
| 规范化单份 target 列表 | 合并 base 与 override 两份 service 列表 |
| 关注 URL 与 timeout | 关注 endpoint、retry 与 service 名称 |
| 保持单份输入的稳定顺序 | 覆盖同名项后仍产生稳定结果 |

复习要验证的是能力迁移：你是否仍能划分 I/O、验证、合并、排序和测试边界，而不是是否记得上一份代码。

## 独立完成规则

本次不提供分步提示、课程引用或参考思路。README、starter、fixture 和可编辑测试就是公开契约；你需要自行决定实现结构和测试组合。

建议先在纸面或注释中回答三个问题：

1. base 中只有的 service、override 中只有的 service、两边同名的 service 分别应如何进入结果？
2. 哪些字段必须在合并前后保持有效？
3. 怎样让输入顺序不同但内容相同的配置产生稳定结果？

## 提交前复验

- Build、Test、Vet 是否都能独立通过？
- 文件读取失败是否保留可判断的原因？
- 重名覆盖、非法值和输出顺序是否都有你自己的测试？
- 实现是否依赖上一任务特有的字段或偶然顺序？

提交后若某项能力未通过，结果页会指出需要补强的方向，并把你带回对应练习；通过则会延长下一次复习间隔。
