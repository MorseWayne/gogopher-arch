# 程序结构：名字、声明、作用域和初始化边界

一个 Go 程序不是由孤立语句堆起来的。变量保存值，表达式组合计算，`if` 和 `for` 控制流程，函数隔离步骤，类型表达领域语义，最后这些名字被组织进源文件与包。

本章用一个后端启动场景来理解程序结构：你要读取配置、设置运行级别、初始化服务，并让失败原因清楚地暴露出来。变量放在哪里、名字是否导出、初始化动作是显式还是隐藏在 `init` 里，都会影响测试、排障和代码评审。

## 你会解决什么问题

假设一个服务启动时要确定运行级别：默认是 `info`，如果配置检查通过就切换到 `ready`，最后输出稳定状态。

```text
level=ready
```

这个小需求会牵出第二章大多数知识：

| 任务 | Go 概念 | 工程关注点 |
|---|---|---|
| 给状态命名 | 标识符、导出规则 | 名字越公开越要清楚 |
| 保存默认值 | `var`、零值、常量 | 零值是否安全可用 |
| 切换状态 | `:=`、`=`、作用域 | 避免遮蔽外层变量 |
| 表达领域概念 | `type`、命名类型 | 不让不同单位随意混用 |
| 初始化服务 | 包、文件、`init` | 副作用要显式可测试 |

## 命名：作用域越大，名字越要清楚

Go 的名字可以用于函数、变量、常量、类型、语句标号和包。名字必须以 Unicode 字母或下划线开头，后续可以跟字母、数字或下划线。大小写敏感，因此 `heapSort` 和 `Heapsort` 是两个不同的名字。

包级名字如果以大写字母开头，就可以被其他包访问；小写开头则只在包内可见。例如 `fmt.Printf` 是导出的，而你自己包里的 `parseConfig` 通常是内部辅助函数。

```go
for i, task := range tasks {
    fmt.Printf("%d: %s\n", i, task.Title)
}
```

这里 `i` 的作用域很小，短名没有问题；`task` 比 `t` 更适合出现在业务逻辑里，因为读者能立即知道当前元素是什么。

命名的判断标准不是“越长越专业”，而是“读者需要追踪多久”。局部循环变量可以短；包级类型、导出函数、跨文件共享变量必须清楚表达业务含义。

## 声明：程序实体从这里出现

Go 主要有四类声明：`var`、`const`、`type` 和 `func`。它们分别定义变量、常量、类型和函数。

每个 `.go` 源文件都从 `package` 声明开始，随后是 `import`，再之后是包级的类型、变量、常量和函数声明。包级声明的顺序通常不重要；函数内部则必须先声明后使用。

```go
package main

import "fmt"

const defaultLevel = "info"

type Level string

func main() {
    var level Level = defaultLevel
    fmt.Println(level)
}
```

| 声明 | 定义什么 | 常见位置 |
|---|---|---|
| `var` | 可变值 | 包级或函数内部 |
| `const` | 编译期常量 | 单位、枚举、默认值 |
| `type` | 命名类型 | 领域概念、接口、结构体 |
| `func` | 可调用行为 | 包级函数或方法 |

声明不是语法装饰，而是在告诉读者：这个名字是什么、在哪里有效、是否会变化、能不能被其他包使用。

## 变量和零值：没有未初始化变量

`var` 声明的一般形式是：

```go
var name type = expression
```

类型和初始化表达式可以省略一个。如果省略类型，Go 根据表达式推断类型；如果省略表达式，变量会被初始化为对应类型的零值。

常见零值包括：数字是 `0`，布尔值是 `false`，字符串是空字符串，指针、slice、map、channel、函数和接口是 `nil`。结构体和数组的零值则是每个字段或元素都取自己的零值。

```go
var retries int
var level string
var ready bool

fmt.Printf("retries=%d level=%q ready=%v\n", retries, level, ready)
```

零值是 Go 设计里很重要的一部分。好的类型设计会尽量让零值安全可用，例如 `bytes.Buffer` 的零值可以直接写入。但对数据库连接、远程客户端、配置文件这类必须依赖外部资源的对象，通常仍然需要构造函数和显式错误处理。

## 短变量声明：方便，但要尊重作用域

函数内部最常见的声明方式是短变量声明：

```go
count := 100
name := "gopher"
```

`:=` 会声明新变量并根据右侧表达式推断类型。它只能用在函数内部，不能用于包级声明。短变量声明很适合局部变量，尤其适合接收带错误返回的函数结果：

```go
f, err := os.Open(name)
if err != nil {
    return err
}
```

要特别注意：`:=` 是声明，不是普通赋值。它左边至少要有一个新变量。如果同一词法域里已有部分变量，那么已有变量会被赋值，新变量会被声明。

```go
in, err := os.Open(infile)
out, err := os.Create(outfile) // out 是新变量，err 被复用
```

但如果你在内层作用域使用 `:=`，它可能创建一个新的同名变量，遮蔽外层变量。

## 指针：地址、别名和修改能力

指针保存另一个变量的地址。`&x` 取得变量 `x` 的地址，`*p` 访问指针 `p` 指向的变量。

```go
x := 1
p := &x
fmt.Println(*p) // 1
*p = 2
fmt.Println(x)  // 2
```

指针让函数可以修改调用方持有的变量，也让多个名字引用同一份状态。这很有用，但也意味着别名会增加理解成本。

```go
func enable(debug *bool) {
    *debug = true
}

func main() {
    debug := false
    enable(&debug)
    fmt.Println(debug)
}
```

只要代码里出现指针、slice、map、channel 或接口包装的可变对象，你都要问：谁还可能看到这个状态？谁可以修改它？并发场景下，这个问题还会进一步变成“谁在什么时候修改”。

## `new`、生命周期和逃逸直觉

`new(T)` 会创建一个 `T` 类型的零值，并返回它的地址：

```go
p := new(int)
fmt.Println(*p) // 0
*p = 42
```

它和下面这种写法效果很接近：

```go
var v int
p := &v
```

Go 中返回局部变量地址是安全的，编译器会根据可达性决定变量放在栈上还是堆上。写正确代码时不需要手动管理内存，但从性能角度要知道：把短生命周期对象的指针保存到长生命周期对象中，可能会让它无法及时回收。

## 赋值和多重赋值

赋值语句更新已有变量：

```go
x = 1
*p = true
person.Name = "bob"
counts[status]++
```

多重赋值会先计算右侧所有表达式，再统一更新左侧变量。这让交换变量和迭代状态更新很自然：

```go
x, y = y, x

func gcd(x, y int) int {
    for y != 0 {
        x, y = y, x%y
    }
    return x
}
```

很多 Go API 通过第二个返回值表达成功与否，例如 `map` 查找、类型断言、channel 接收和返回 `error` 的函数调用。空白标识符 `_` 可以丢弃不需要的值，但不要滥用它掩盖错误。

```go
value, ok := cache[key]
if !ok {
    return "", fmt.Errorf("cache miss: %s", key)
}
```

## 类型声明：让相同底层结构表达不同概念

`type` 声明创建一个新的命名类型。即使底层类型相同，不同命名类型也代表不同概念。

```go
type Celsius float64
type Fahrenheit float64

func CToF(c Celsius) Fahrenheit {
    return Fahrenheit(c*9/5 + 32)
}
```

`Celsius` 和 `Fahrenheit` 都以 `float64` 为底层类型，但不能随意混用。这样可以避免把摄氏温度和华氏温度直接相加一类的业务错误。

类型转换 `Celsius(x)` 会改变编译器如何看待这个值，但不会自动完成单位换算；真正的换算应该放进函数。

## 包、文件和初始化顺序

包用于模块化、封装、单独编译和复用。一个包可以有多个 `.go` 文件；同一个包里的包级类型、变量、常量和函数可以互相访问。每个文件的 `import` 只对当前文件生效，不能被同包其他文件共享。

包初始化遵循确定顺序：先初始化导入的包，再初始化当前包的包级变量，最后执行 `init` 函数，`main` 包最后初始化并进入 `main` 函数。

`init` 适合做小而确定的初始化，例如预计算查表数据。但它不适合承担复杂副作用，比如读取生产配置、打开网络连接、连接数据库或启动 goroutine。现代服务更推荐显式初始化：

```go
func main() {
    cfg, err := LoadConfig()
    if err != nil {
        log.Fatal(err)
    }

    app, err := NewApp(cfg)
    if err != nil {
        log.Fatal(err)
    }

    log.Fatal(app.Run())
}
```

这种写法比把逻辑藏在 `init` 里更容易测试，也更容易在启动失败时定位原因。

## 作用域：编译期的可见范围

作用域是源代码中名字有效的文本范围。函数体、循环体、`if`、`switch` 都会引入词法块。编译器解析名字时，会从最内层作用域向外查找。内部声明会遮蔽外部同名声明。

```go
var cwd string

func init() {
    cwd, err := os.Getwd() // cwd 是新的局部变量
    if err != nil {
        log.Fatal(err)
    }
    log.Println(cwd)
}
```

这段代码看起来更新了包级 `cwd`，但实际上 `:=` 在 `init` 内创建了新的局部 `cwd`。正确写法是先声明 `err`，再用普通赋值更新外层变量：

```go
var cwd string

func init() {
    var err error
    cwd, err = os.Getwd()
    if err != nil {
        log.Fatal(err)
    }
}
```

Go 的常见错误处理风格也和作用域有关。通常不要把正常路径放进很深的 `else` 里，而是在错误分支直接返回，让成功路径保持左对齐。

```go
f, err := os.Open(name)
if err != nil {
    return err
}
defer f.Close()

return readFrom(f)
```

## 概念回看：程序结构怎么支撑可维护性

| 概念 | 定义形式 | 语义模型 | 常见误区 |
|---|---|---|---|
| 名字 | `level`、`LogLevel` | 作用域越大，名字越要清楚 | 包级名字含糊或过度导出 |
| 声明 | `var` / `const` / `type` / `func` | 创建程序实体 | 把声明顺序当成函数执行顺序 |
| 零值 | 省略初始化表达式 | 自动得到类型默认值 | 把零值和未填写混淆 |
| 短变量声明 | `name := value` | 函数内声明新变量 | 在内层作用域遮蔽外层变量 |
| 指针 | `&x`、`*p` | 多个名字可共享同一状态 | 忽略别名和并发修改风险 |
| 命名类型 | `type Level string` | 给底层类型增加领域含义 | 以为类型转换会做业务换算 |
| 包初始化 | 包级变量、`init`、`main` | 导入包先初始化 | 在 `init` 里放复杂副作用 |
| 作用域 | 词法块 | 编译期名字查找范围 | 和生命周期混为一谈 |

## 本章工程视角

程序结构决定代码能否被人理解和安全修改。变量放在最小作用域，错误路径紧跟调用点，初始化显式发生，类型表达领域概念，这些选择都比“语法能不能运行”更影响长期维护。

完成本章后，你应该能检查这几件事：

- `:=` 是否真的需要声明新变量。
- 包级变量是否有清楚所有者和初始化方式。
- `init` 是否只做小而确定的工作。
- 命名类型是否表达了业务含义，而不是只包装基础类型。
- 正常路径是否被错误处理压到很深的嵌套里。
