# 程序结构：名字、声明、作用域和初始化

一个 Go 程序不是由孤立语句堆起来的。变量保存值，表达式组合计算，`if` 和 `for` 控制流程，函数隔离和复用步骤，最后这些函数、类型和变量被组织进源文件与包。《Go 程序设计语言》第 2 章的重点就是拆开这些基础构件，说明名字如何生效、值如何被创建、包如何初始化。

对于后端工程来说，程序结构不是语法细节，而是可维护性的边界。一个变量放在函数内还是包级，一个名字是否导出，一个初始化动作是在 `main` 中显式发生还是在 `init` 中隐式发生，都会影响测试、排障和代码评审。

## 命名：作用域越大，名字越要清楚

Go 的名字可以用于函数、变量、常量、类型、语句标号和包。名字必须以 Unicode 字母或下划线开头，后续可以跟字母、数字或下划线。大小写敏感，因此 `heapSort` 和 `Heapsort` 是两个不同的名字。

Go 还有一个非常重要的导出规则：包级名字如果以大写字母开头，就可以被其他包访问；小写开头则只在包内可见。例如 `fmt.Printf` 是导出的，而你自己包里的 `parseConfig` 通常是内部辅助函数。

命名时不要机械追求长或短。Go 社区常见风格是：局部变量可以短，比如循环里的 `i`、`v`、`err`；作用域越大、生命周期越长，名字就越应该表达清楚。包级类型、导出函数和跨文件共享变量尤其不能含糊。

```go
for i, task := range tasks {
    fmt.Printf("%d: %s\n", i, task.Title)
}
```

这里 `i` 的作用域很小，短名没有问题；`task` 比 `t` 更适合出现在业务逻辑里，因为读者能立即知道当前元素是什么。

## 声明：程序实体从这里出现

Go 主要有四类声明：`var`、`const`、`type` 和 `func`。它们分别定义变量、常量、类型和函数。

每个 `.go` 源文件都从 `package` 声明开始，随后是 `import`，再之后是包级的类型、变量、常量和函数声明。包级声明的顺序通常不重要；函数内部则必须先声明后使用。

```go
package main

import "fmt"

const boilingF = 212.0

func main() {
    var f = boilingF
    var c = (f - 32) * 5 / 9
    fmt.Printf("boiling point = %g°F or %g°C\n", f, c)
}
```

这个例子里，`boilingF` 是包级常量，`f` 和 `c` 是 `main` 函数里的局部变量。局部变量只在函数内部可见，包级名字则可以在同一个包的多个文件中访问。

## 变量和零值：没有未初始化变量

`var` 声明的一般形式是：

```go
var name type = expression
```

类型和初始化表达式可以省略一个。如果省略类型，Go 根据表达式推断类型；如果省略表达式，变量会被初始化为对应类型的零值。

常见零值包括：数字是 `0`，布尔值是 `false`，字符串是空字符串，指针、slice、map、channel、函数和接口是 `nil`。结构体和数组的零值则是每个字段或元素都取自己的零值。

```go
var total int
var title string
var ready bool

fmt.Println(total, title, ready) // 0 "" false
```

零值是 Go 设计里很重要的一部分。好的类型设计会尽量让零值安全可用，例如 `bytes.Buffer` 的零值可以直接写入。但对必须提供外部资源的对象，例如数据库连接或远程客户端，通常仍然需要构造函数和显式错误处理。

## 短变量声明：方便，但要尊重作用域

函数内部最常见的声明方式是短变量声明：

```go
count := 100
name := "gopher"
```

`:=` 会声明新变量并根据右侧表达式推断类型。它只能用在函数内部，不能用于包级声明。短变量声明简洁灵活，适合局部变量，尤其适合接收带错误返回的函数结果：

```go
f, err := os.Open(name)
if err != nil {
    return err
}
```

要特别注意：`:=` 是声明，不是普通赋值。它左边至少要有一个新变量。如果同一词法域里已有部分变量，那么已有变量会被赋值，新变量会被声明。

```go
in, err := os.Open(infile)
out, err := os.Create(outfile) // out 是新变量，err 被复用
```

但如果你在内层作用域使用 `:=`，它可能创建一个新的同名变量，遮蔽外层变量。这是 Go 初学者最常见的 bug 之一。

```go
level := 1
if passed {
    level := 2 // 新变量，只在 if 内有效
    _ = level
}
fmt.Println(level) // 仍然是 1
```

需要更新外层变量时，应使用 `=`：

```go
level := 1
if passed {
    level = 2
}
```

## 指针：地址、别名和修改能力

指针保存另一个变量的地址。`&x` 取得变量 `x` 的地址，`*p` 访问指针 `p` 指向的变量。

```go
x := 1
p := &x
fmt.Println(*p) // 1
*p = 2
fmt.Println(x)  // 2
```

指针让函数可以修改调用方持有的变量，也让多个名字引用同一份状态。这很有用，但也意味着别名会增加理解成本。只要代码里出现指针、slice、map、channel 或接口包装的可变对象，你都要问：谁还可能看到这个状态？谁可以修改它？

Go 中返回局部变量地址是安全的，编译器会根据可达性决定变量分配在栈还是堆上。写正确代码时不需要手动管理内存，但从性能角度要知道：把短生命周期对象的指针保存到长生命周期对象中，可能会让它无法及时回收。

## 赋值和多重赋值

赋值语句更新已有变量：

```go
x = 1
*p = true
person.Name = "bob"
counts[status]++
```

多重赋值会先计算右侧所有表达式，再统一更新左侧变量。这让交换变量和迭代状态更新很自然：

```go
x, y = y, x

func gcd(x, y int) int {
    for y != 0 {
        x, y = y, x%y
    }
    return x
}
```

很多 Go API 通过第二个返回值表达成功与否，例如 `map` 查找、类型断言、channel 接收和返回 `error` 的函数调用。空白标识符 `_` 可以丢弃不需要的值，但不要滥用它掩盖错误。

```go
value, ok := cache[key]
if !ok {
    return "", fmt.Errorf("cache miss: %s", key)
}
```

## 类型声明：让相同底层结构表达不同概念

`type` 声明创建一个新的命名类型。即使底层类型相同，不同命名类型也代表不同概念。

```go
type Celsius float64
type Fahrenheit float64

func CToF(c Celsius) Fahrenheit {
    return Fahrenheit(c*9/5 + 32)
}
```

`Celsius` 和 `Fahrenheit` 都以 `float64` 为底层类型，但不能随意混用。这样可以避免把摄氏温度和华氏温度直接相加一类的业务错误。类型转换 `Celsius(x)` 会改变编译器如何看待这个值，但不会自动完成单位换算；真正的换算应该放进函数。

命名类型还可以拥有方法。比如为温度类型实现 `String` 方法后，`fmt` 打印时可以输出带单位的文本。这是把领域语义放进类型系统的第一步。

## 包、文件和初始化顺序

包用于模块化、封装、单独编译和复用。一个包可以有多个 `.go` 文件；同一个包里的包级类型、变量、常量和函数可以互相访问。每个文件的 `import` 只对当前文件生效，不能被同包其他文件共享。

包初始化遵循确定顺序：先初始化导入的包，再初始化当前包的包级变量，最后执行 `init` 函数，`main` 包最后初始化并进入 `main` 函数。

`init` 适合做小而确定的初始化，例如预计算查表数据。但它不适合承担复杂副作用，比如读取生产配置、打开网络连接、连接数据库或启动 goroutine。现代服务更推荐显式初始化：

```go
func main() {
    cfg, err := LoadConfig()
    if err != nil {
        log.Fatal(err)
    }

    app, err := NewApp(cfg)
    if err != nil {
        log.Fatal(err)
    }

    log.Fatal(app.Run())
}
```

这种写法比把逻辑藏在 `init` 里更容易测试，也更容易在启动失败时定位原因。

## 作用域：编译期的可见范围

作用域是源代码中名字有效的文本范围，是编译期概念；生命周期是运行时变量存在的时间。不要把二者混在一起。

函数体、循环体、`if`、`switch` 都会引入词法块。编译器解析名字时，会从最内层作用域向外查找。内部声明会遮蔽外部同名声明。

```go
var cwd string

func init() {
    cwd, err := os.Getwd() // 错误：cwd 是新的局部变量
    if err != nil {
        log.Fatal(err)
    }
    log.Println(cwd)
}
```

这段代码看起来更新了包级 `cwd`，但实际上 `:=` 在 `init` 内创建了新的局部 `cwd`。正确写法是先声明 `err`，再用普通赋值更新外层变量：

```go
var cwd string

func init() {
    var err error
    cwd, err = os.Getwd()
    if err != nil {
        log.Fatal(err)
    }
}
```

Go 的常见错误处理风格也和作用域有关。通常不要把正常路径放进很深的 `else` 里，而是在错误分支直接返回，让成功路径保持左对齐：

```go
f, err := os.Open(name)
if err != nil {
    return err
}
defer f.Close()

return readFrom(f)
```

这不仅更符合 Go 风格，也让变量作用域和资源生命周期更容易看清楚。
