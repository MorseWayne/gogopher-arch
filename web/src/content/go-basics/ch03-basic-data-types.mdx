# 基础数据类型：用类型表达业务边界

从底层看，程序处理的都是比特；从业务看，我们处理的是订单金额、用户昵称、状态开关、时间戳、文件大小和 JSON 文本。基础数据类型就是这两层之间的桥梁。

本章用一个 API 入参处理场景进入基础类型：你要接收用户昵称、订单金额、分页大小和状态开关，并把它们转换成稳定、可检查、不会误导后续代码的值。类型选择不是语法细节，而是业务边界设计。

## 你会解决什么问题

假设一个后端接口收到这些信息：

```text
nickname="Go语言"
amount_cents=1999
page_size=20
enabled=true
```

你需要判断：昵称长度按字节还是字符？金额能不能用 `float64`？分页大小用 `int` 还是 `int64`？状态开关能不能用 `0`/`1` 代替？这些问题都属于基础数据类型的工程选择。

| 任务 | Go 类型 | 工程关注点 |
|---|---|---|
| 表示计数和索引 | `int`、`int64` | 平台边界、协议边界 |
| 表示金额和比例 | 整数最小单位、`float64` | 精度和舍入 |
| 表示条件 | `bool` | 不做隐式真假转换 |
| 表示文本 | `string`、`byte`、`rune` | UTF-8、字节数、码点数 |
| 表示稳定枚举 | `const`、`iota`、命名类型 | 可读性和非法状态 |

## 整数：默认用 `int`，跨边界要说清

Go 提供多种整数类型：`int8`、`int16`、`int32`、`int64`，以及对应的无符号类型 `uint8`、`uint16`、`uint32`、`uint64`。还有两个很常见的别名：`byte` 等价于 `uint8`，常用于原始字节；`rune` 等价于 `int32`，常用于 Unicode 码点。

`int` 和 `uint` 的大小与平台有关，通常是 32 或 64 位。日常循环计数、slice 索引、`len` 返回值通常使用 `int`。跨平台协议、数据库 ID、Unix 毫秒时间戳这类字段更适合明确使用 `int64` 或业务命名类型。

```go
var retries int = 3
var userID int64 = 922337203685477580
var b byte = 'A'
var r rune = '界'

fmt.Println(retries, userID, b, r)
```

整数运算可能溢出。Go 不会在普通整数溢出时自动报错；超出范围的高位会被丢弃。

```go
var u uint8 = 255
fmt.Println(u, u+1) // 255 0

var i int8 = 127
fmt.Println(i, i+1) // 127 -128
```

不要只因为值“不应该为负”就盲目使用 `uint`。例如倒序循环如果使用无符号数，很容易因为 `i >= 0` 永远成立而出错。除非你在做位运算、二进制协议、哈希或加密，普通业务数量通常使用有符号整数更省心。

## 显式转换让类型边界可见

Go 不会在不同整数类型之间隐式转换。即使 `int32` 和 `int` 在某些平台上大小相同，它们也是不同类型。

```go
var apples int32 = 1
var oranges int16 = 2
// var total int = apples + oranges // 编译错误

var total = int(apples) + int(oranges)
fmt.Println(total)
```

这种严格性减少了隐式溢出和精度损失。代价是你需要在边界处写清转换意图。工程代码里，类型转换往往意味着“跨单位、跨协议、跨存储边界”，值得被代码评审重点关注。

```go
type Cents int64

total := Cents(1999)
fmt.Println(total)
```

命名类型能把“这不是普通整数”写进类型系统。它不能替你做所有校验，但能让调用点更容易读出业务含义。

## 浮点数：适合测量，不适合金额

Go 有 `float32` 和 `float64`。通常优先使用 `float64`，因为它精度更高，也更符合标准库数学函数的默认选择。

浮点数是近似值。它适合科学计算、比例、统计指标和图形计算，但不适合需要精确十进制的小数，例如金额。金额通常应使用整数最小货币单位，比如 cents，或者使用专门 decimal 类型。

浮点还包含特殊值：正无穷、负无穷和 `NaN`。`NaN` 和任何值都不相等，包括它自己。

```go
nan := math.NaN()
fmt.Println(nan == nan) // false
```

如果一个浮点计算可能失败，不要只返回 `NaN` 让调用者猜。更好的做法是返回额外状态或错误：

```go
func ratio(done, total float64) (float64, bool) {
    if total == 0 {
        return 0, false
    }
    return done / total, true
}
```

## 布尔值：条件必须是真的 bool

布尔值只有 `true` 和 `false`。`if`、`for` 条件和比较表达式都使用布尔值。Go 不会把数字自动转成布尔值，也不会把布尔值自动转成 `0` 或 `1`。

```go
if count > 0 {
    fmt.Println("has items")
}
```

`&&` 和 `||` 有短路行为。这个特性常用于先检查边界，再访问数据：

```go
if s != "" && s[0] == 'x' {
    fmt.Println("starts with x")
}
```

如果 `s` 是空字符串，右侧的 `s[0]` 不会被求值，因此不会 panic。

## 字符串是只读字节序列

Go 字符串是不可变的字节序列。它可以保存任意字节，但通常保存 UTF-8 文本。`len(s)` 返回字节数，不是用户看到的字符数。

```go
s := "Hello, 世界"
fmt.Println(len(s)) // 13
```

英文字符通常占 1 个字节，中文字符通常占 3 个字节。因此，字符串的第 `i` 个字节不一定是第 `i` 个字符。按字节切片也可能切断一个 UTF-8 字符，得到非法文本。

字符串不可变，不能修改其中某个字节：

```go
s := "left foot"
// s[0] = 'L' // 编译错误
s = "right foot" // 可以让变量指向新字符串
```

不可变让字符串复制和切片很便宜，因为多个字符串值可以安全共享底层数据。但这也意味着逐步拼接大量字符串可能产生许多分配，工程上常用 `strings.Builder` 或 `bytes.Buffer` 构造大字符串。

## Unicode、UTF-8、byte 和 rune

Unicode 为世界上各种字符分配码点，Go 用 `rune` 表示一个 Unicode 码点。UTF-8 是把码点编码为字节序列的变长编码，ASCII 字符占 1 字节，常见中文占 3 字节，部分 emoji 可能更复杂。

Go 源文件使用 UTF-8，字符串也很适合保存 UTF-8 文本。要按码点遍历字符串，使用 `range`：

```go
for i, r := range "Hello, 世界" {
    fmt.Printf("%d\t%q\n", i, r)
}
```

这里的 `i` 是字节索引，不是第几个字符；`r` 是当前 rune。要统计 rune 数量，可以使用：

```go
title := "Go语言"
fmt.Println(len(title))        // 8 字节
fmt.Println(len([]rune(title))) // 4 个 rune
```

注意，rune 数量也不总等于用户感知的“字符数”。某些 emoji、组合音标和复杂文字可能由多个码点组成。对于用户可见长度限制，需要更高层的文本分段库或产品规则。

## 标准库字符串工具

常用字符串相关包包括：

- `strings`：查询、替换、切分、拼接、大小写转换；
- `bytes`：处理 `[]byte`，API 与 `strings` 类似；
- `strconv`：字符串与数字、布尔值之间转换；
- `unicode`：按 Unicode 规则判断字母、数字、大小写；
- `unicode/utf8`：UTF-8 编码和解码。

实际项目里，不要手写所有字符串处理逻辑。比如路径 basename、前缀判断、分隔符拼接、数字解析，都应优先看看标准库是否已经提供了清楚、经过测试的实现。

```go
id, err := strconv.ParseInt("42", 10, 64)
if err != nil {
    return err
}
fmt.Println(id)
```

字符串和数字转换是典型边界：HTTP 查询参数、JSON 字段、环境变量和命令行参数进来时都是文本，进入业务逻辑前应该被转换成明确类型，并处理失败情况。

## 常量：编译期确定的值

常量在编译期计算，不能在运行期修改。它适合表达数学常数、枚举值、固定单位、位标志和数组长度。

```go
const timeoutSeconds = 30
const defaultPageSize = 20
```

Go 的无类型常量很强大。它们在赋值或使用时才被转换为具体类型，因此可以直接用于多种数值上下文。

```go
const secondsPerMinute = 60
var timeout int64 = 5 * secondsPerMinute
```

常量组可以省略重复表达式。配合 `iota`，可以生成连续枚举或位标志。

```go
type Status int

const (
    StatusPending Status = iota
    StatusRunning
    StatusPassed
    StatusFailed
)
```

位标志常用 `1 << iota`：

```go
type Flags uint

const (
    FlagActive Flags = 1 << iota
    FlagAdmin
    FlagBeta
)
```

这类常量在权限、状态开关和协议字段里很常见。但不要为了“高级”而滥用位标志；如果业务需要清晰可读，普通布尔字段或枚举结构可能更好。

## 复数：知道它存在，但不作为后端主线

gopl-zh 第 3 章还介绍了复数类型 `complex64` 和 `complex128`。它们在科学计算、信号处理和某些图形算法里有价值，但普通后端业务很少直接使用。

本课程不会把复数作为主练习目标。你需要知道 Go 原生支持复数，也需要知道“语言支持”不等于“业务里应该使用”。当你的项目真的需要它时，再回到标准库和数学背景里系统学习。

## 概念回看：基础类型如何表达边界

| 概念 | 定义形式 | 语义模型 | 常见误区 |
|---|---|---|---|
| 整数 | `int`、`int64`、`uint8` | 固定位宽或平台相关位宽 | 用 `uint` 表达所有非负数 |
| 显式转换 | `int64(x)` | 编译器不会自动跨类型转换 | 以为转换会做业务单位换算 |
| 浮点数 | `float64` | 二进制近似值 | 用它表示精确金额 |
| 布尔值 | `true` / `false` | 条件必须是 bool | 用 `0`、`1` 代替真假 |
| 字符串 | `string` | 只读字节序列，通常是 UTF-8 | 把字节长度当字符长度 |
| rune | `rune` / `int32` | Unicode 码点 | 以为 rune 数就是用户感知字符数 |
| byte | `byte` / `uint8` | 原始字节 | 把字节切片直接当文本处理 |
| 常量 | `const`、`iota` | 编译期确定 | 过度使用位标志降低可读性 |
| 无类型常量 | `const n = 60` | 使用时才落到具体类型 | 忽略赋值目标的范围限制 |

## 本章工程视角

基础类型不是语法表，而是业务模型的材料。一个字段使用 `int`、`int64`、`string`、`bool`、`float64` 还是自定义命名类型，会影响 JSON 表示、数据库 schema、测试边界和未来重构。

在代码评审中，看到这些地方要停下来确认：金额是否使用浮点？时间单位是否写清？字符串长度是否按字节判断？ID 是否可能超过 `int32`？零值是否和“未填写”冲突？如果这些问题在类型选择阶段处理好，后续很多 bug 都不会出现。
