优化方案对比

三种不同深度的改造策略，覆盖你关心的全部 5 个方向

A

渐进式精细化（推荐）

保持三栏骨架，在现有结构上做深度打磨

  • 响应式：增强断点（1120px → 960px → 760px），面板可收起/展开
  • 视觉：统一 8px 间距系统、字体层级（display / heading / body / caption）
  • 交互：拖拽调整三栏宽度、面板折叠按钮、运行状态动画
  • 编辑器：保持 Monaco，优化工具栏和文件标签展示
  • 组件化：按面板拆分为 TaskPanel / EditorPanel / FeedbackPanel / TopBar
B

IDE 式工作台（激进重构）

借鉴 VS Code 布局模式，编辑器最大化

  • 左侧 Activity Bar 图标切换不同功能面板（任务、反馈、知识地图）
  • 中间代码编辑器占据绝大部分空间
  • 底部可抽出控制台/终端
  • 面板可自由拖拽、浮动、堆叠
  • 移动端：底部 Tab Bar 替代 Activity Bar
C

最小可行优化（快速交付）

只改 CSS 和少量结构，不动骨架

  • 响应式：微调媒体查询断点
  • 视觉：调整 padding、font-size、边框颜色
  • 不添加拖拽交互
  • 不大幅拆分组件
  • 1-2 天内可完成

Trade-off 对比

维度 A 渐进式 B IDE 式 C 最小化
改动量 中等 大 小
交付周期 3-5 天 1-2 周 1 天
风险 低 中高 极低
编辑器空间 良好 极佳 不变
移动端 友好 很友好 基本可用
我的推荐：方案 A（渐进式精细化）

理由：当前三栏布局对于"任务驱动学习"场景其实是合理的（左侧任务、中间编码、右侧反馈），不需要推翻重来。方案 A 在保持用户已有心智模型的前提下，把响应式、视觉、交互、组件化都做扎实，性价比最高。后续如果确实需要 IDE 式体验，可以再演进。
